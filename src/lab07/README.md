## Задание A. Поиск (`search.py`)

```python
def linear_search(nums, x):
    """Индекс первого вхождения x или -1."""
    for index, value in enumerate(nums):
        if value == x:
            return index
    return -1


def binary_search(sorted_nums, x):
    """Индекс x в отсортированном списке или -1.

    На неотсортированном списке результат не определён.
    """
    lo = 0
    hi = len(sorted_nums) - 1

    while lo <= hi:
        mid = (lo + hi) // 2
        value = sorted_nums[mid]

        if value == x:
            return mid
        if value < x:
            lo = mid + 1
        else:
            hi = mid - 1

    return -1


def two_sum_brute(nums, target):
    """Пара индексов (i, j), i < j, или None. Перебор всех пар, O(n²)."""
    for i in range(len(nums)):
        for j in range(i + 1, len(nums)):
            if nums[i] + nums[j] == target:
                return (i, j)
    return None


def two_sum_fast(nums, target):
    """То же через словарь «значение -> индекс» за один проход, O(n)."""
    seen = {}

    for index, value in enumerate(nums):
        need = target - value
        if need in seen:
            return (seen[need], index)
        if value not in seen:
            seen[value] = index

    return None
```

`binary_search` возвращает индекс любого вхождения, если число повторяется.
Для `two_sum_fast` при нескольких ответах допустим любой; словарь хранит
первый индекс встреченного значения.

## Задание B. Сортировки (`sorting.py`)

Все три функции начинают с `result = list(nums)`, поэтому исходный список
не меняется. Пустой список и список из одного элемента обрабатываются
циклами естественно — отдельные проверки не нужны.

```python
def bubble_sort(nums):
    result = list(nums)

    for end in range(len(result) - 1, 0, -1):
        swapped = False
        for i in range(end):
            if result[i] > result[i + 1]:
                result[i], result[i + 1] = result[i + 1], result[i]
                swapped = True
        if not swapped:          # ранний выход: обменов не было
            break

    return result


def insertion_sort(nums):
    result = list(nums)

    for i in range(1, len(result)):
        value = result[i]
        j = i - 1
        while j >= 0 and result[j] > value:
            result[j + 1] = result[j]
            j -= 1
        result[j + 1] = value

    return result


def selection_sort(nums):
    result = list(nums)

    for i in range(len(result) - 1):
        min_index = i
        for j in range(i + 1, len(result)):
            if result[j] < result[min_index]:
                min_index = j
        if min_index != i:
            result[i], result[min_index] = result[min_index], result[i]

    return result
```

В пузырьке есть флаг `swapped`: если за очередной проход обменов не было,
список уже отсортирован и оставшиеся проходы не нужны.

## Задание C. Проверка против эталона (`check.py`)

`check_sorting(fn, trials=100)` генерирует 100 случайных списков длиной
от 0 до 50 со значениями от −100 до 100; проверка запускается для каждой
из трёх сортировок. Для каждого списка проверяется:

1. `fn(nums) == sorted(nums)` — результат совпадает с эталоном;
2. `nums == original` — исходный список не изменён.

`check_search()` сравнивает `linear_search` с `list.index` (для отсутствующего
элемента эталон — `-1`), а `binary_search` — с отсортированным списком:
проверяется, что найденный индекс действительно указывает на `x`, а для
отсутствующего `x` возвращается `-1`. Отдельно проверяются пустой список,
список из одного элемента и крайние значения.

`check_two_sum()` сравнивает оба решения: они должны одновременно найти
ответ или одновременно вернуть `None`, а найденная пара — удовлетворять
`i < j` и `nums[i] + nums[j] == target`.

Итого: 3 × 100 прогонов сортировок, 100 раундов поиска и 100 случайных
раундов Two Sum плюс 6 фиксированных случаев. Каждый assert увеличивает
общий счётчик, поэтому в конце печатается точное число проверок.

Запуск:

```bash
python -m src.lab07.check
```

Результат на `random.seed(42)`:

```text
OK: 2814 проверок
```

Расхождений не найдено, поэтому исправлять алгоритмы не пришлось.
Проверка сразу ловит и типичную ошибку «забыли скопировать список»:
она упала бы на `assert nums == original`, даже если сортировка правильная.

## Задание D. Бенчмарк (`bench.py`)

Замеры выполняются через `timeit.timeit(..., number=1)` внутри отдельного
процесса. Это нужно для честного ограничения квадратичных сортировок:
если замер на 100 000 элементов идёт дольше `--timeout` секунд (по умолчанию
60), процесс завершается, а в таблицу попадает `> 60`.

Данные генерируются один раз на каждое `n` и подаются всем алгоритмам
одинаковыми. Зерно `random.seed(42)`, поэтому запуск воспроизводим.
Для поиска используются один отсортированный список из 100 000 чисел
и 10 000 одинаковых запросов для линейного и бинарного поиска.
Время сортировки этого списка вынесено отдельной строкой.
В Two Sum `target = 10^9` гарантированно достигается парой, спрятанной
в конце списка, поэтому перебор пар не находит ответ в самом начале.

Запуск:

```bash
python -m src.lab07.bench
python -m src.lab07.bench --timeout 10 --out data/lab07/bench_quick.csv
```

## Выводы

При росте `n` с 1 000 до 10 000 пузырёк замедлился в 116 раз
(0.013771 → 1.599265 с), вставки — в 118 раз, выбор — примерно в 100 раз.
Это ожидаемо: все три алгоритма делают порядка `n²/2` сравнений, а при
увеличении `n` в 10 раз `n²` увеличивается в 100 раз. Небольшое отличие
от 100 — накладные расходы Python, ветвления и работа с памятью. `sorted`
замедлился только в 12.5 раза (0.000050 → 0.000620 с), потому что Timsort
работает за `O(n log n)`: при `n × 10` время растёт примерно в
`10 × log(10n)/log(n)` раз, то есть около 12–13. На 100 000 элементов
квадратичные сортировки не уложились в 60 секунд, а `sorted` справился
за 0.008 с — разница уже в тысячи раз.

Линейный поиск сделал 10 000 запросов к списку из 100 000 элементов
за 9.49 с, бинарный — за 0.0076 с, то есть примерно в 1 250 раз быстрее.
Но бинарному поиску нужен отсортированный список: сортировка 100 000
элементов заняла 0.0079 с, а один линейный запрос — около 0.00095 с.
Значит, сортировка окупается примерно после 8–9 запросов к одному и тому
же списку. Если запрос один, проще линейный поиск; если данных много
и запросов много, сортировка плюс бинарный поиск выгоднее. Если список
уже отсортирован, бинарный поиск выгоден сразу.

Two Sum через словарь оказался быстрее перебора пар примерно в 154 раза
на `n = 1 000` (0.010326 → 0.000067 с) и примерно в 2 680 раз на
`n = 10 000` (1.082548 → 0.000404 с). Перебор делает `O(n²)` проверок, а словарь —
один проход `O(n)`: для каждого числа достаточно проверить, встречалось ли
уже `target - x`. Поэтому при увеличении `n` в 10 раз перебор замедлился
примерно в 105 раз, а быстрый вариант — всего в 6 раз.

## Краевые случаи

- Пустой список: сортировки возвращают `[]`, поиск возвращает `-1`,
  `two_sum` возвращает `None`.
- Список из одного элемента: сортировка возвращает копию, бинарный поиск
  корректно находит элемент или возвращает `-1`.
- Повторы: `linear_search` возвращает первое вхождение, `binary_search` —
  любое, `two_sum_fast` не использует один и тот же индекс дважды.
- Отрицательные числа и отсутствующий `x`: покрыты случайными проверками
  и явными краевыми случаями в `check.py`.
- Квадратичная сортировка на 100 000: ограничена таймаутом, в таблице
  помечена как `> 60`, а не выдаётся за измеренное число.
